의도적으로 고른 설정

03

데이터에서 내린 결정

①도움말 소비 19.4% — 온보딩 비용이 과도하다

전체 탭 전환의 5분의 1이 도움말이었다. 기능이 아니라 쓰는 법을 찾는 행위에 사용자 시간이 쓰이고 있다는 신호로 읽었다.

②전술 타임라인 에디터 0.2% — 기능을 제거했다

852건 중 2건. 개발 비용 대비 사용량이 사실상 0인 기능을 데이터로 확인하고 걷어냈다. 감이 아니라 수치로 기능의 존폐를 판단할 근거를 확보한 사례다.

③방문자 33%에서 rageclick — 마찰 지점을 특정했다

27명 중 9명에게서 클릭이 반응하지 않는 지점이 자동 수집됐다. 해당 세션을 리플레이로 되돌려 실제 원인을 확인하는 흐름을 구축했다.

④로그인이 진입 장벽으로 작동했다

autocapture에 로그인 · 회원가입 · Google로 계속하기 클릭이 각각 39 · 46 · 16건 남은 반면, 로그인 이후에만 도달 가능한 지표는 그에 비례해 늘지 않았다. 이후 제품은 로그인을 완전히 제거하고 브라우저 로컬 저장 기반으로 전환했다 — 가입 없이 즉시 도구를 쓰는 구조다.

⑤데스크톱 98.6% — 모바일 대응을 뒤로 미뤘다

모바일에 리소스를 쓰는 대신 데스크톱의 밀도 높은 표 UI에 집중하는 판단의 근거로 썼다.

04

개인정보 자체 감사와 조치

지표를 얻는 것과 사용자 데이터를 필요 이상으로 쥐고 있는 것은 다른 문제라고 보고, 수집한 데이터를 직접 재감사했다.

발견

  • 로그인 제거 이후 person 프로필 0건 — 익명 단위로만 분석되도록 설정돼 있음을 확인.
  • 다만 이벤트에 IP와 도시 단위 위치가 남아 있었다.
  • autocapture 클릭 텍스트에 실명 1건이 저장돼 있었다.
  • 서비스 개발이 끝난 뒤에도 세션 리플레이 수집이 계속되고 있었다.

조치

  • 조치 완료세션 리플레이 수집 중단 (session_recording_opt_in: false)
  • 조치 완료IP 익명화 활성 (anonymize_ips: true) — 이후 이벤트에서 IP를 저장하지 않음
  • 조치 완료autocapture 중단 (autocapture_opt_out: true) — 클릭 텍스트에 실명이 수집되던 경로를 차단
  • 조치 완료콘솔 로그 · 성능 · 히트맵 캡처 중단
  • 조치 완료잔여 녹화본 삭제 — 현재 저장된 세션 리플레이 0건
  • 자동 만료측정 기간의 녹화본 93건은 30일 보존 정책에 따라 이미 만료됨
보고서 정정

초판에는 93세션 · 123.7MB가 보존 중이라고 적었으나, 재확인 결과 이는 이벤트에 남은 세션 메타데이터였고 재생 가능한 녹화본은 30일 보존 정책으로 이미 만료된 상태였다. 실제로 남아 있던 1건은 배포 검증용 접속 기록이었고 삭제했다.

05

이 분석의 한계

  • 표본 27명 규모의 클로즈드 베타 데이터로, 통계적 유의성을 주장할 수 있는 규모가 아니다.
  • 위 결정들은 상관 관찰에 기반하며, A/B 테스트로 인과를 검증한 결과가 아니다.
  • 측정 기간이 5.5주로 짧아 리텐션 코호트 분석은 수행하지 않았다.

규모를 과장하지 않는 편이 이 기록의 쓸모에 맞다고 봤다. 여기서 얻은 것은 통계적 결론이 아니라, 만든 것이 쓰이는지 재보고 그 결과로 결정을 바꾸는 절차다.
