## 01 · 계측 설계

분석 도구를 붙이는 데서 끝내지 않고, **무엇을 알아야 결정을 내릴 수 있는가**를
먼저 정의한 뒤 최소한의 이벤트만 심었다.

| 계측 항목 | 설계 의도 |
|---|---|
| `tab_change` (커스텀) | 어떤 기능이 실제로 쓰이는지 — 기능별 투자 우선순위 판단 |
| `character_fetch` (커스텀, `character_count` 포함) | 핵심 가치 행동 도달 여부와 실제 사용 규모 |
| `$pageview` / `$pageleave` | 방문·이탈 기준선 |
| Autocapture | 사전에 예상하지 못한 클릭 경로 회수 |
| `$rageclick` | UX 마찰 지점 자동 탐지 |
| Web Vitals | 실사용 환경의 체감 성능 |
| Session Replay | 정량 지표로 설명되지 않는 이탈의 원인 확인 |

### 의도적으로 고른 설정

- `capture_pageview: false` + 수동 캡처 — App Router의 클라이언트 라우팅에서
  페이지뷰가 누락되거나 중복되는 문제를 직접 제어하기 위해.
- `person_profiles: "identified_only"` — 로그인이 없는 서비스이므로 불필요한
  개인 프로필 생성을 차단. 실제 저장된 프로필 0건.
- 환경변수가 없으면 SDK 자체를 초기화하지 않음 — 로컬·프리뷰 트래픽이
  프로덕션 지표를 오염시키지 않도록.

## 02 · 측정 결과

### 기능별 사용 비중

탭 전환 852건 / 16명. 사용자 1인당 평균 **53회** 전환 — 한 번 들어온 사용자는
얕게 훑고 나가는 게 아니라 여러 기능을 오가며 실제 업무에 썼다.

| 탭 | 전환 수 | 비중 | |
|---|---|---|---|
| 공대 거래 | 243 | 28.5% | |
| 파티원 명단 | 236 | 27.7% | |
| 공대 분석 | 206 | 24.2% | |
| 도움말 | 165 | **19.4%** | ← 온보딩 비용이 과도하다는 신호 |
| 전술 타임라인 에디터 | 2 | **0.2%** | ← 만들었지만 쓰이지 않는 기능 |

### 핵심 행동

`character_fetch` **39회**, 누적 **557 캐릭터** 조회, 회당 평균 **14.3명**(최대 23명).
회당 14~23명은 실제 공격대 편성 단위와 일치한다 — 테스트성 클릭이 아니라
실사용 데이터임을 확인한 근거다.

### 체감 성능 · Web Vitals p75 (460 샘플)

| 지표 | 값 | 기준 | 판정 |
|---|---|---|---|
| LCP | 2,400ms | ≤ 2,500ms | Good |
| INP | 56ms | ≤ 200ms | Good |
| CLS | 0.007 | ≤ 0.1 | Good |
| FCP | 2,364ms | — | 참고값 |

상호작용 응답성(INP)과 레이아웃 안정성(CLS)은 기준을 크게 상회한다.
초기 렌더(LCP·FCP)는 기준선을 겨우 통과하는 수준이라 개선 여지가 남은 영역으로 식별했다.

> **이 값은 실사용자 필드 측정**이며, 별도로 기록한 Lighthouse 랩 측정치
> (3.3s → 1.9s)와는 측정 조건이 다르다.

## 03 · 데이터에서 내린 결정

**① 도움말 소비 19.4% — 온보딩 비용이 과도하다**
전체 탭 전환의 5분의 1이 도움말이었다. 기능이 아니라 **쓰는 법을 찾는 행위**에
사용자 시간이 쓰이고 있다는 신호로 읽었다.

**② 전술 타임라인 에디터 0.2% — 기능을 제거했다**
852건 중 2건. 개발 비용 대비 사용량이 사실상 0인 기능을 데이터로 확인하고 걷어냈다.
감이 아니라 수치로 기능의 존폐를 판단할 근거를 확보한 사례다.

**③ 방문자 33%에서 rageclick — 마찰 지점을 특정했다**
27명 중 9명에게서 클릭이 반응하지 않는 지점이 자동 수집됐다. 해당 세션을
리플레이로 되돌려 실제 원인을 확인하는 흐름을 구축했다.

**④ 로그인이 진입 장벽으로 작동했다**
autocapture에 `로그인` · `회원가입` · `Google로 계속하기` 클릭이 각각 39 · 46 · 16건
남은 반면, 로그인 이후에만 도달 가능한 지표는 그에 비례해 늘지 않았다.
이후 제품은 **로그인을 완전히 제거하고 브라우저 로컬 저장 기반으로 전환**했다 —
가입 없이 즉시 도구를 쓰는 구조다.

**⑤ 데스크톱 98.6% — 모바일 대응을 뒤로 미뤘다**
모바일에 리소스를 쓰는 대신 데스크톱의 밀도 높은 표 UI에 집중하는 판단의 근거로 썼다.

## 04 · 개인정보 자체 감사와 조치

지표를 얻는 것과 사용자 데이터를 필요 이상으로 쥐고 있는 것은 다른 문제라고 보고,
수집한 데이터를 직접 재감사했다.

### 발견

- 로그인 제거 이후 **person 프로필 0건** — 익명 단위로만 분석되도록 설정돼 있음을 확인.
- 다만 이벤트에 **IP와 도시 단위 위치**가 남아 있었다.
- autocapture 클릭 텍스트에 **실명 1건**이 저장돼 있었다.
- 서비스 개발이 끝난 뒤에도 **세션 리플레이 수집이 계속되고 있었다.**

### 조치

| 상태 | 내용 |
|---|---|
| 조치 완료 | 세션 리플레이 수집 중단 (`session_recording_opt_in: false`) |
| 조치 완료 | IP 익명화 활성 (`anonymize_ips: true`) — 이후 이벤트에서 IP를 저장하지 않음 |
| 조치 완료 | autocapture 중단 (`autocapture_opt_out: true`) — 클릭 텍스트에 실명이 수집되던 경로를 차단 |
| 조치 완료 | 콘솔 로그 · 성능 · 히트맵 캡처 중단 |
| 조치 완료 | 잔여 녹화본 삭제 — 현재 저장된 세션 리플레이 **0건** |
| 자동 만료 | 측정 기간의 녹화본 93건은 30일 보존 정책에 따라 이미 만료됨 |

### 보고서 정정

초판에는 *93세션 · 123.7MB가 보존 중*이라고 적었으나, 재확인 결과 이는 이벤트에 남은
**세션 메타데이터**였고 재생 가능한 녹화본은 30일 보존 정책으로 이미 만료된 상태였다.
실제로 남아 있던 1건은 배포 검증용 접속 기록이었고 삭제했다.

## 05 · 이 분석의 한계

- 표본 27명 규모의 클로즈드 베타 데이터로, **통계적 유의성을 주장할 수 있는 규모가 아니다.**
- 위 결정들은 상관 관찰에 기반하며, A/B 테스트로 인과를 검증한 결과가 아니다.
- 측정 기간이 5.5주로 짧아 리텐션 코호트 분석은 수행하지 않았다.

규모를 과장하지 않는 편이 이 기록의 쓸모에 맞다고 봤다. 여기서 얻은 것은 통계적
결론이 아니라, **만든 것이 쓰이는지 재보고 그 결과로 결정을 바꾸는 절차**다.
